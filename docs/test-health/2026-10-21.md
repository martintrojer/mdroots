## Findings

- **The slow tests are file-creation bound.** `discover` itself never
  took over 50 ms alone (357 ms under load); the rest is writing thousands
  of files at 0.35–2.4 ms each on this host. Linux CI pays far less.
- **Proptest time was the RNG, not the code under test.** opt-level 1 on
  `mdroots-syntax` gave nothing (6.3 s → 6.1 s); opt-level 1 on proptest,
  rand, rand_core, rand_chacha, rand_xorshift and ppv-lite86 took
  `fragments_stay_in_their_segment` 6.3 s → 0.4 s and the totality tests
  ~2.5 s → 0.15 s. Workspace crates keep the plain dev profile.
- **`fixture_01`** ran 81 `git init`s; only `repo07` and `scratch/repo03`
  are opened. The other 38 get a bare `.git` dir, which is all marker
  detection checks (`markers.rs`), and the tree is built once for both
  cases. 20 s → 3.7 s.
- **`fixture_03_slow_listings`** built the same 6,000-file tree as
  `fixture_03_dense`; merged into it. The slow run needs a fresh
  `MemRegistry` (a reused one answers from the stored `~/notes` row and
  never walks) and its own ticking `Counting<HomeProbe>` (the clock only
  moves forward; counters are per probe).
- **`fixture_09`**'s untracked tree shrank 2,000 → 100 files. It asserts
  `read_dir_total() == 0`, and any walk lists the root before a budget can
  stop it, so size never mattered; 2,000 files was under every budget
  anyway. Spec wording changed from "large" to "an untracked tree".
- **The two big `reconcile` tests** run on `MemFs` with a real temp
  `IndexDb`. Batching lives in `reconcile.rs` (200 files or 50 ms), not in
  the DB, and doesn't depend on the filesystem. 18 s → 0.2 s each.

## Rejected or refuted

- **Removing `FS_LOCK`.** Its old reason (wall budgets) went with the fake
  clock in `3637c4b`, but it still guards the real-time 1 s assert in
  `timed()`; discover measured up to 357 ms under load, and 13 tree-writing
  tests at once would eat that headroom. Under nextest it is a no-op; under
  `cargo test` it serialises the fixtures binary.
- **Moving `TMPDIR` under `target/`**: inconclusive, not adopted.
- **`many_process` `HOLD_MS` floor** (~3 s each): low priority, left.
